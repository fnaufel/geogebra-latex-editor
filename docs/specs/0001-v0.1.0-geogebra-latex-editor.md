# v0.1.0 — LaTeX Text Editor for GeoGebra

**Status:** Accepted; ready for implementation after repository commit

**Target release:** 0.1.0

**Implementation readiness:** `ready-for-agent`

**Product name:** LaTeX Text Editor for GeoGebra

**Deployment:** Non-commercial static GitHub Pages application

This specification is authoritative for v0.1.0 behavior and acceptance. The canonical domain language is defined in [CONTEXT.md](../../CONTEXT.md); architectural rationale is recorded in [the ADRs](../adr/). If this specification appears to conflict with the glossary or an ADR, stop and reconcile the documents before implementing.

## Problem Statement

GeoGebra can create dynamic LaTeX text, but authoring mixed literal LaTeX and object-dependent expressions through its native text workflow is cumbersome. Every dynamic value interrupts the literal string, requiring users to construct nested quoted strings, concatenations, and text-producing commands manually. The resulting GeoGebra definition is difficult to read and cannot be converted reliably back into the source the author intended.

Users need a browser application in which they can open or create a GeoGebra construction, choose a text object, edit one readable LaTeX body with embedded GeoGebra expressions, and safely compile that Authoring Source into a dynamic GeoGebra text definition. The downloaded `.ggb` must remain a normal, self-contained GeoGebra file and must carry enough metadata to restore the Authoring Source in another browser.

## Solution

Build a local-first, two-pane web application containing GeoGebra Classic and a CodeMirror 6 editor. The editor owns one pinned Editing Target at a time. Its Authoring Source is a LaTeX body in which `@expression@` denotes a GeoGebra Interpolation and `@@` denotes a literal at sign.

A pure compiler separates Literal Segments from interpolations, validates a conservative Value Expression subset, and generates a Compiled Definition composed of GeoGebra text concatenations. Each interpolation is rendered through `FormulaText`; the complete text uses `FormulaText` and, by default, `Simplify(Text)`. Applying a valid draft redefines the existing text object while preserving its identity and presentation, updates the embedded Authoring Source metadata, verifies both changes, and creates one GeoGebra undo point.

The application stores a versioned, UTF-8 base64url metadata envelope in an invisible, fixed, non-selectable auxiliary GeoGebra text object. Opening and downloading use browser-local file operations. Recovery Drafts and a local construction snapshot live only in IndexedDB, expire after 30 days, and are never uploaded. There is no backend, account system, analytics, or telemetry.

## Implementation Decisions

### 1. Product and release boundary

- V0.1.0 is a non-commercial, local-first desktop web application. It has no server-side application, database, user accounts, cloud storage, collaboration, analytics, or telemetry.
- The displayed product name is **LaTeX Text Editor for GeoGebra**. The page must visibly say **Unofficial · Made with GeoGebra®** and link to the project source, GeoGebra license, and GeoGebra terms.
- Application code uses the MIT License. GeoGebra code, assets, trademarks, and bundled materials remain governed by their own licenses. Project documentation must state that commercial deployment requires separate GeoGebra authorization.
- The app is built and tested locally, then its static assets are published from the `gh-pages` branch to GitHub Pages.
- V0.1.0 targets current desktop browsers. Touch-first/mobile authoring and offline/self-hosted GeoGebra are later work.

### 2. Technology baseline

- Use strict TypeScript, Vite, CodeMirror 6, standards-based DOM APIs, Vitest, and Playwright.
- Use a framework-free browser interface. UI state belongs to the Construction Workspace rather than an implicit framework lifecycle.
- At implementation start, select and pin the then-current active LTS Node release, package manager version, dependency lockfile, and formatter/linter versions. Local checks and builds must use the pinned toolchain.
- Embed GeoGebra Classic and pin the production applet to version `5.4.920.0`, the version used for the empirical spikes behind this specification. Upgrade only through a tested dependency change.
- Capture the applet through `appletOnLoad(ggbApi)`; never depend on the global `ggbApplet`, which may refer to the last active applet.
- Configure GeoGebra with its construction toolbar visible and undo/redo enabled. Hide its menu bar, input/file features, sign-in, and cloud-file controls. The surrounding application owns New, Open, and Download.

### 3. Principal modules and test seams

The codebase has four principal modules. Each exposes one small interface to callers and tests.

1. **Source Compiler**
   - Pure and deterministic: no DOM, GeoGebra, browser storage, time, locale, or network access.
   - Accepts Authoring Source, target-independent compile options, the safe command catalog, and a construction symbol snapshot.
   - Returns parsed segments, proven global references, diagnostics with source ranges, and either a target-independent compiled text expression or no expression.
   - Never evaluates a GeoGebra expression.

2. **GeoGebra Adapter**
   - Owns applet lifecycle, version checks, file import/export, object queries, selection and construction listeners, event normalization, text creation/adoption/redefinition, metadata-object persistence, presentation snapshots, postcondition verification, rollback, and GeoGebra undo points.
   - Converts all applet callbacks into a documented internal event union. Callers never consume GeoGebra's raw array/object client events.
   - Exposes semantic operations such as creating a managed text or applying a compiled text state, rather than mirroring the large GeoGebra method surface.

3. **Construction Workspace**
   - Owns Editing Target, GeoGebra selection, Applied Source, per-object Draft Source, divergence, orphan state, dirty flags, filename, insertion state, recovery state, diagnostics, and user-intent transitions.
   - Orchestrates the Source Compiler and GeoGebra Adapter.
   - Is the primary application test seam. A deterministic in-memory GeoGebra adapter is used for workspace tests; the production adapter is checked by browser contract tests.

4. **Browser Interface**
   - Renders the workspace state and turns browser/CodeMirror/DOM events into workspace actions.
   - Contains no source compilation, metadata encoding, GeoGebra command construction, or recovery policy.
   - Is tested through accessible roles, names, and externally visible state.

Do not introduce additional external seams until two real adapters or callers require them. Internal helpers may exist inside these modules without becoming caller-visible interfaces.

### 4. Authoring Source grammar

The v1 source language is version 1 and uses this grammar:

```ebnf
document      = { literal-char | literal-at | interpolation } ;
interpolation = "@" expression "@" ;
literal-at    = "@@" ;
literal-char  = ? any character except "@" ? ;
```

Required scanner behavior:

- Use a deterministic stateful scanner, not regular-expression replacement.
- In a Literal Segment, `@@` emits one literal at sign and a single `@` opens an interpolation.
- Inside an interpolation, the next `@` closes it. Therefore `@` is unavailable inside an expression, including inside a GeoGebra string.
- `@a@@b@` is two adjacent interpolations: the first middle at sign closes `a`, and the second opens `b`.
- An unmatched delimiter is an error at its exact source range.
- A zero-length or whitespace-only interpolation is an error. Outside an interpolation, `@@` is a literal and never an empty interpolation.
- Interpolations may span lines. Normalize CRLF and CR to LF, then compile all source LF characters to ordinary spaces. Explicit LaTeX `\\` remains the rendered line-break mechanism.
- Preserve tabs and spaces other than normalized line endings in v1.
- Preserve every LaTeX backslash exactly once in the actual string passed to GeoGebra. Host-language escaping is an implementation concern and must not alter the payload.
- Literal ASCII `"` cannot appear inside a GeoGebra quoted string. Split the literal at each quote and emit `UnicodeToLetter(34)` as a concatenated term.
- Coalesce adjacent Literal Segments and omit empty literal terms.
- The empty document compiles to an empty LaTeX text and remains a valid Managed Text Object.

### 5. Value Expression validation and completion

- Interpolations accept object labels, literals, operators, parentheses, lists, pure built-in mathematical functions, and allowlisted single-result commands.
- Accept GeoGebra's coordinate variables `x`, `y`, and `z`; boolean literals; and standard constants such as π, ℯ, and the imaginary unit without requiring them to exist as construction labels.
- Command names in Authoring Source are English regardless of the GeoGebra UI locale. Completion inserts the English form.
- The v1 command seed catalog is:
  - `FormulaText`
  - `FractionText`
  - `SurdText`
  - `ScientificText`
  - `TableText`
  - `VerticalText`
  - `Ordinal`
  - `UnicodeToLetter`
  - `Name`
  - `Text`
  - `Simplify`
  - `If`
- The catalog records supported arities/overloads, result cardinality, and any locally bound argument positions. Only cataloged single-result overloads are valid. For example, `Text` overloads that merely produce one text value are valid; overloads or commands whose contract would create or mutate unrelated construction objects are absent.
- The initial pure built-in function catalog is `abs`, `sgn`, `sqrt`, `exp`, `log`, `ln`, `ld`, `lg`, `cos`, `sin`, `tan`, `acos`, `arcos`, `arccos`, `asin`, `arcsin`, `atan`, `arctan`, `atan2`, `cosh`, `sinh`, `tanh`, `acosh`, `arcosh`, `arccosh`, `asinh`, `arcsinh`, `atanh`, `arctanh`, `erf`, `floor`, `ceil`, `round`, `conjugate`, `arg`, `gamma`, `gammaRegularized`, `beta`, `betaRegularized`, `sec`, `csc`, `cosec`, `cot`, `sech`, `csch`, and `coth`. The non-deterministic `random` function is excluded.
- Validation lexes quoted strings and balanced delimiters before identifying command calls and object references. It must not identify names inside GeoGebra strings as references.
- Resolve labels against a symbol snapshot made from GeoGebra object names, types, and defined state. Do not assume labels are ASCII identifiers; use exact applet labels and GeoGebra naming rules.
- A label absent from the construction creates an Unresolved Interpolation error and disables Apply.
- A referenced object that exists but is currently undefined creates an Undefined Value Expression warning and does not disable Apply.
- Unknown commands, action/scripting commands, raw label assignments, and known multi-output commands are errors. Validation is recursive, including inside `If`.
- Mathematical equality may remain a Value Expression when the validator can classify both sides as expressions. Root-level syntax that could create or redefine a label is rejected. The final interpolation is always nested inside the labeled text definition and is never evaluated as an independent command.
- Raw interpolation text is never sent to `evalCommand` for validation. Only the final labeled text definition may be evaluated in the live construction.
- Rename propagation uses the validated reference map. It updates only proven global references and respects command-local bindings. Ambiguous tokens remain unchanged and produce a manual-resolution diagnostic.
- Outside interpolations, completion offers a curated GeoGebra-supported LaTeX catalog rather than a complete TeX distribution.
- Inside interpolations, completion offers exact current object labels, safe commands, safe functions, constants, and syntax appropriate to the cursor.
- The supported catalogs are versioned application data, covered by tests, and reproduced in user documentation.

### 6. Compilation contract

For each valid source:

1. Compile a Literal Segment to one or more GeoGebra text terms.
2. Compile each GeoGebra Interpolation to `FormulaText((expression))`. The double parentheses isolate operator precedence.
3. Concatenate the terms with `+`.
4. With Sign Simplification disabled, compile the complete expression as `FormulaText(concatenatedText)`.
5. With Sign Simplification enabled, compile it as `FormulaText(Simplify(concatenatedText))`.
6. Prefix the expression with the Editing Target label only inside the GeoGebra Adapter when applying.
7. Generate the target definition as one physical line. The adapter may join the target and metadata assignments with a single command-separator newline when applying the verified pair.

The motivating example compiles approximately as follows; this shape came from the GeoGebra prototype and is normative, while harmless whitespace is not:

```text
text1=FormulaText(Simplify(
  FormulaText((a))+" x^2 + "+FormulaText((b))+
  " x = "+FormulaText((a))+" \left( x^2 + "+
  FormulaText((FractionText(b/a)))+" x \right)"
))
```

The actual command sent to GeoGebra is one line; the displayed line breaks are for readability.

The compiler result contains:

- normalized source;
- ordered Literal Segment and GeoGebra Interpolation nodes with source ranges;
- proven global object references and their ranges;
- errors and warnings with stable codes, severity, message, and range;
- the target-independent compiled text expression when no error exists;
- a deterministic fingerprint input for metadata and recovery.

Do not include `Simplify` anywhere else in the default path. Segment-level simplification and inline protection syntax are not supported.

### 7. Sign Simplification

- New Managed Text Objects default to Sign Simplification enabled.
- Adopted objects default to Sign Simplification disabled.
- A clearly labeled per-object control, **Clean signs and 1x coefficients**, appears beside the editor and is stored with Applied Source.
- Its help text states that GeoGebra performs a global, non-LaTeX-aware string rewrite.
- The documentation and control must include concrete warnings: `\text{C++}` becomes content equivalent to `\text{C + }`, and `\text{--}` becomes content equivalent to `\text{ + }`.
- Changing the control changes Draft Source options and therefore requires Apply. It does not mutate the object immediately.

### 8. Metadata envelope

Store one construction-wide metadata envelope in a GeoGebra text object. The decision-rich v1 shape is:

```json
{
  "application": "geogebra-latex-editor",
  "schemaVersion": 1,
  "languageVersion": 1,
  "documents": {
    "<stable-document-uuid>": {
      "targetLabel": "text1",
      "source": "Authoring Source",
      "simplify": true,
      "compiledFingerprint": "sha256:<post-apply-command-fingerprint>"
    }
  }
}
```

- Serialize deterministically as UTF-8 JSON, encode as unpadded base64url, and store the encoded value as independent text.
- The metadata object is invisible in Graphics View, auxiliary, fixed, and non-selectable.
- Prefer the exact label `gglatexEditorMetadataV1`. If it collides with an object that is not valid owned metadata, choose the next available `gglatexEditorMetadata_<n>` label and never overwrite the collision.
- Discover candidates by the ASCII-letter-leading prefix `gglatexEditorMetadata`, then require object type `text`, successful base64url/JSON decoding, the exact application marker, and a supported schema version.
- Leading-underscore labels are invalid in the tested applet and must not be used.
- Compute `compiledFingerprint` from the normalized post-Apply English command returned by the pinned GeoGebra runtime, not solely from pre-evaluation source. Store the observed normalized form long enough to make recovery conservative. A failure to match is acceptable; a false attachment is not.
- Preserve unknown newer metadata bytes unchanged. The app may render the construction and expose affected texts as unmanaged, but must not adopt, migrate, or overwrite newer metadata without explicit confirmation.
- Supported older schema/language versions migrate in memory. Original loaded bytes remain recoverable until the user successfully downloads the migrated construction.
- An absent, deleted, malformed, undecodable, or unsupported envelope does not make the `.ggb` invalid. Generated texts remain ordinary GeoGebra objects and Authoring Source becomes unavailable.
- The implementation must establish and document a tested minimum capacity of 1 MiB of decoded JSON and at least 100 managed records without truncation. If the auxiliary-object carrier cannot meet that bound, stop implementation and revise the metadata ADR rather than shipping silent limits.

### 9. Applet lifecycle and event normalization

- Use GeoGebra Classic with the pinned version and public HTML5 API.
- The GeoGebra Adapter registers dedicated add, update, remove, rename, and clear listeners plus a generic client listener.
- Normalize both documented client-event objects and empirically observed array events. The tested runtime emitted arrays such as `["select","t",""]`, `["deselect",""]`, `["undo",""]`, and `["redo",""]`.
- Maintain GeoGebra selection from normalized select/deselect events; there is no assumed `getSelectedObjects()` repair API.
- Use the dedicated rename listener for exact old/new labels and the dedicated remove listener for deleted labels.
- A selected-object rename may emit deselect-all. Repair Editing Target and metadata identity through the dedicated rename event before processing generic selection consequences.
- On clear/new construction, move retained sources to orphan/recovery state only after the applicable dirty-work confirmation.
- Treat `evalCommand`'s boolean as advisory. Empirical tests showed direct action commands can mutate objects while returning `false`, and some selection commands can work while returning `false`. Verify semantic postconditions instead.

### 10. Editing Target, selection, and insertion

- Editing Target and GeoGebra selection are independent workspace fields.
- Selecting an object never changes the Editing Target automatically.
- **Edit selected text** is enabled only when exactly one selected object has GeoGebra type `text`.
- For a Managed Text Object, load Applied Source plus any retained Draft Source.
- For an Unmanaged Text Object, show the current rendered LaTeX read-only and offer Adoption.
- Insertion Mode is one-shot. After activation, exactly one subsequently selected object inserts `@<exact-label>@` at the CodeMirror cursor, returns focus to CodeMirror, and exits.
- A multi-selection inserts nothing, retains Insertion Mode, and announces that one object is required.
- Escape any at signs when creating Literal Source during Adoption: each literal `@` becomes `@@`.
- New Managed Text asks GeoGebra to choose the next conventional text label, creates it near the current visible canvas center, persists its initial metadata, makes it the Editing Target, and places editor focus in an empty Draft Source.

### 11. Editor states and controls

The right pane must render these explicit states:

- no Editing Target;
- Managed Text Object with clean Applied Source;
- Managed Text Object with Draft Source;
- Diverged Draft;
- Unmanaged Text Object adoption view;
- Orphaned Source;
- incompatible/corrupt metadata notice;
- applying;
- recoverable Apply error.

The editor area includes:

- Editing Target label and object status;
- CodeMirror editor or read-only adoption view;
- **Clean signs and 1x coefficients** control;
- diagnostics with keyboard navigation and non-color severity indicators;
- dirty/diverged/orphan status;
- Apply, Reapply, Discard, Adopt, Restore, and Insert Object actions as applicable;
- an Advanced disclosure showing the one-line Compiled Definition with a copy action.

Debounce source parsing, completion refresh, known-object validation, and compiled-definition generation by 300 ms after the latest edit. Apply performs immediate validation again. V1 has no rendered live preview and never evaluates during debounce.

Apply uses `Ctrl+Enter` on Windows/Linux and `Command+Enter` on macOS in addition to its button. Standard CodeMirror undo/redo remains scoped to Draft Source.

### 12. Apply protocol and presentation invariants

A successful Apply must:

1. Revalidate current Draft Source and object state.
2. Confirm that the target still exists and is a text object.
3. Snapshot the target definition, position, color, layer, visibility, caption/label visibility, fixed/selection state, absolute-screen-position state, LaTeX flag, font/style properties, selection state, and current metadata envelope.
4. Produce a labeled target redefinition and the encoded metadata assignment.
5. Submit the two valid assignments as one grouped applet operation.
6. Verify that the target exists, remains a text object, has the intended current command/value, and retained all presentation invariants.
7. Verify that metadata decodes exactly to the intended envelope.
8. Create exactly one GeoGebra undo point only after verification.
9. Promote Draft Source to Applied Source, clear its draft/recovery marker, and mark the construction dirty.

If any step fails, restore both snapshots, verify restoration, retain Draft Source, and report a stable diagnostic. Metadata failure always rolls back the visible text change.

Empirical tests showed labeled redefinition preserved label, common color/font/layer settings, label visibility, and selection. The implementation must also verify positioned FormulaText, absolute screen position, visibility, fixed/selectionAllowed, caption, and advanced style variants before relying on preservation. Snapshot and reapply any property the runtime does not preserve.

### 13. History and resynchronization

- CodeMirror history changes Draft Source only.
- GeoGebra history changes Applied Source and construction state.
- Applying target plus metadata creates one GeoGebra history boundary.
- Keep the GeoGebra toolbar visible because the tested applet ignored undo/redo when `showToolBar` was false even with undo enabled.
- GeoGebra undo/redo did not emit ordinary object update callbacks in the tested runtime. Normalize generic undo/redo client events and schedule a full target/metadata resynchronization after the applet operation completes.
- Guard programmatic editor replacement so resynchronization does not create a draft or recursive Apply.
- When history changes Applied Source under a dirty draft, preserve the draft, refresh the applied baseline, and mark it Diverged. Reapply and Discard are explicit.

### 14. Rename, delete, and external-edit behavior

- When the Editing Target is renamed in the live applet, update its metadata record, editor header, selection key, and recovery keys without changing its stable document UUID.
- When any referenced object is renamed, use the compiler's proven reference map to rewrite exact references in Applied Source, Draft Source, and Recovery Drafts. Strings, local variables, and ambiguous tokens remain unchanged.
- The live rename plus Applied Source metadata rewrite must behave as one construction-history action. Undo/redo must restore both labels and source references together; if the pinned runtime cannot support this invariant, stop and revise the history ADR before shipping.
- When a referenced object is deleted, mark affected source with Unresolved Interpolation errors. Preserve source; never substitute literal text.
- When the Editing Target is deleted, retain its metadata record as Orphaned Source. Undo reattaches when label/fingerprint identity is unambiguous; otherwise offer Restore as new or Discard.
- On load after edits in another GeoGebra installation, first match the stored target label. If absent, compare the stored post-Apply fingerprint against text objects and reattach only one exact, unique match. Otherwise retain Orphaned Source and expose candidates without guessing.

### 15. Adoption

- Adoption is explicit and requires confirmation that prior dependencies will not be recovered.
- Read the object's current rendered LaTeX, escape literal at signs for Authoring Source, and create one Literal Segment.
- Sign Simplification starts disabled.
- Apply the new metadata without changing the object's visible definition unless normalization is necessary; preserve every presentation property.
- Adoption creates one GeoGebra undo point. Undo returns the object to unmanaged state and removes its metadata record.
- V1 does not provide raw GeoGebra-definition editing or best-effort reverse parsing.

### 16. File lifecycle

- **New** creates a blank construction only after resolving dirty drafts and a Dirty Construction.
- **Open .ggb** uses a standard browser file picker and reads the file locally as base64. Stage and validate the candidate in a separate temporary applet/context before replacing the visible workspace. A failed stage leaves the active applet, filename, drafts, recovery identifiers, and dirty flags unchanged.
- Opening initializes metadata, managed/unmanaged/orphan states, construction fingerprint, and recovery candidates only after successful staging.
- **Download .ggb** exports through `getBase64`, converts locally to a Blob, and dispatches a browser download. For an opened `lesson.ggb`, default to `lesson-edited.ggb`; for a new construction, default to `construction.ggb`. The download dialog allows an override.
- When drafts exist, Download offers:
  1. apply all valid drafts and download;
  2. download the coherent Applied State only;
  3. cancel.
- If any chosen Apply fails, cancel the download and preserve the workspace.
- Mark the construction clean after export succeeds and the browser download is dispatched; browsers do not provide a portable OS-level save-completion signal.
- Leave unapplied drafts dirty after downloading Applied State only.
- Track all applet construction changes, not only editor Apply, when setting Dirty Construction.
- Register a browser `beforeunload` warning whenever a dirty draft or Dirty Construction exists.

### 17. Local recovery and multiple tabs

- IndexedDB stores Recovery Drafts, their Applied Source baselines, workspace identity, source options, timestamps, and a local base64 construction snapshot sufficient to recover a new or interrupted workspace. Persisting the construction snapshot is an explicit implementation assumption required for crash recovery; it remains browser-local under the same privacy and retention rules.
- Key recovery records by a SHA-256 construction fingerprint plus a generated workspace identifier. A new unsaved construction uses its workspace identifier until it gains a downloaded/opened fingerprint.
- Offer matching recovery on page load or after the corresponding construction opens. Show metadata and age before exposing source; never apply automatically.
- Prune records older than 30 days and clear records after explicit application or discard.
- Provide **Clear local recovery data** and report how much local data will be removed.
- Use `BroadcastChannel` or an equivalent browser-local presence mechanism to warn when another live tab has the same construction fingerprint. Tabs remain independent and never merge, lock, or synchronize source.
- Recovery remains useful if the metadata object was lost: recovered source may be presented as Orphaned Source and requires explicit restoration.

### 18. Failure handling and diagnostics

- GeoGebra bundle failure shows a retryable loading error; file/editor mutation actions remain disabled until a version-checked applet is ready.
- File-stage failure leaves the current workspace intact.
- Metadata absence/corruption/newer version leaves the construction usable and prevents destructive metadata writes.
- Compiler diagnostics use stable codes and exact ranges.
- Runtime Apply diagnostics distinguish compiler rejection, missing target, GeoGebra rejection, postcondition mismatch, metadata failure, rollback success, and rollback failure.
- A rollback failure is a high-severity state: stop further Apply operations, preserve Draft and snapshot data locally, allow immediate Download of the recoverable construction if possible, and instruct the user to reload or report the diagnostic.
- Provide copy/download of a sanitized diagnostic report containing application version, browser identity, pinned GeoGebra version, stable error codes, and a bounded event history.
- Exclude `.ggb` contents, object values/definitions, Authoring Source, metadata payload, filenames, and recovery contents by default. A separate explicit confirmation may add selected content.

### 19. Layout and accessibility

- Use a resizable horizontal split with GeoGebra on the left and the editor on the right.
- Put New, Open, Download, filename, Dirty Construction state, and recovery access in a shared top toolbar.
- The split control, toolbar, dialogs, editor actions, disclosures, and diagnostics are keyboard-operable and expose semantic names/roles.
- Focus is visible and deliberately restored after dialogs, Adoption, Apply, and Insertion Mode.
- Errors, warnings, dirty state, and divergence use text/icons as well as color and meet normal contrast requirements.
- Announce asynchronous state changes such as insertion success, Apply failure, and recovery availability through an appropriate live region without excessive chatter.
- Accessibility inside the embedded GeoGebra applet is upstream-dependent and must be documented honestly.

### 20. Deployment, privacy, and operations

- The application performs network requests only for its own static assets and the pinned GeoGebra bundle/resources.
- Construction files, metadata, diagnostics, and recovery content are never sent to an application server.
- No analytics, telemetry, advertising, cookies for tracking, or third-party error reporting are included.
- Production uses GitHub Pages. Run the required checks locally, build locally, and publish the resulting static files from `gh-pages`; this repository has no GitHub CI workflow.
- The production build handles the repository subpath correctly and uses a Content Security Policy compatible with the pinned GeoGebra embed without broadening sources beyond what the applet demonstrably requires.
- If GeoGebra's license or CDN policy changes, deployment stops until the new terms are reviewed. Do not infer commercial rights from the source-code license.

## Testing Decisions

### Test philosophy and seams

- Test behavior through module interfaces and rendered user behavior. Do not couple tests to private helper structure, DOM class names, or raw GeoGebra callback implementation.
- The highest routine seam is the Construction Workspace with an in-memory GeoGebra adapter. It covers state transitions, orchestration, dirty flags, recovery, and failure behavior without a browser applet.
- The Source Compiler is tested as a pure module because its language contract is independently deep and deterministic.
- The production GeoGebra Adapter is tested through a real pinned applet in browser contract tests.
- A small number of Playwright journeys cover the complete Browser Interface through accessible roles and visible outcomes.
- There is no prior test code in this greenfield repository. The empirical spike behaviors listed under Further Notes are the prior art and must become durable contract tests.

### Source Compiler tests

Cover at minimum:

- empty source;
- literal-only source;
- one, multiple, and adjacent interpolations;
- `@@`, literal at signs around interpolations, and all unmatched-delimiter positions;
- empty and whitespace-only interpolation errors;
- CRLF, CR, LF, tabs, spaces, Unicode, combining characters, and long lines;
- literal quotation splitting through `UnicodeToLetter(34)`;
- exact LaTeX backslash preservation;
- command generation with Sign Simplification on and off;
- the motivating `a`/`b`/`FractionText` example;
- safe catalog commands and every supported overload;
- nested safe commands;
- unknown, action, assignment, and multi-output rejection;
- missing references versus existing undefined values;
- labels containing Unicode, underscores, and subscripts;
- identifiers in GeoGebra strings not becoming references;
- proven global rename updates and non-updates in strings/local scopes;
- stable diagnostic codes/ranges;
- stable normalized compiler/fingerprint output;
- fuzz/property tests showing the scanner terminates, preserves literal content according to the grammar, and never emits an expression when errors exist.

### Metadata tests

Cover at minimum:

- deterministic JSON serialization;
- UTF-8 base64url round-trip for quotes, backslashes, LF, `λ✓漢字`, and large source;
- exact application/schema/language validation;
- prefix discovery and valid suffixed labels;
- collision without overwrite;
- wrong object type;
- malformed base64url and JSON;
- missing marker;
- older recognized migration;
- unknown newer preservation without rewrite;
- missing target and orphan record;
- unique fingerprint recovery and ambiguous no-op;
- the 1 MiB/100-record minimum capacity;
- ordinary `.ggb` export into a fresh applet and exact metadata decode after reload.

### Construction Workspace tests

Use the in-memory adapter to cover:

- initial/no-target state;
- explicit target pinning independent of selection;
- managed and unmanaged target loading;
- Adoption confirmation and source escaping;
- per-object drafts and target switching;
- debounce versus immediate Apply validation;
- Insertion Mode success, multi-selection, cancellation, and focus intent;
- Apply success, compiler failure, runtime failure, metadata failure, rollback, and rollback failure;
- Sign Simplification defaults for new/adopted objects;
- Apply All Valid and Download Applied State Only;
- separate draft/construction dirty flags;
- browser unload/New/Open prompts;
- undo/redo resynchronization;
- Diverged Draft reapply/discard;
- referenced-object rename/delete;
- Editing Target rename/delete/undo/orphan restoration;
- clear/new construction;
- staged file success and failure;
- incompatible metadata read-only behavior;
- recovery offer/apply/discard/prune/clear;

### GeoGebra Adapter browser contract tests

Run against the pinned GeoGebra Classic version and assert:

- applet readiness and exact version;
- base64 New/Open/Download round-trip;
- object creation with GeoGebra-assigned label near visible center;
- selection event normalization for both object and array shapes through fixtures, plus the live runtime shape;
- dedicated rename/remove listener behavior;
- a live referenced-object rename and its source-metadata rewrite undo/redo together as one construction-history action;
- labeled text redefinition preserves identity, position, absolute-screen position, selection, visibility, layer, label/caption, fixed/selectionAllowed, LaTeX flag, color, and font/style properties;
- target plus metadata update under one undo point;

- stage failure leaves the visible applet unchanged.

Automate at least:

1. Create a construction, create number objects and a Managed Text Object, author the motivating formula, apply it, change values, and observe dynamic text update.

3. Open an unmanaged text, adopt it, edit, apply, undo, and redo.
4. Pin a target, use Insertion Mode on another object, and apply the inserted reference.

8. Exercise download choices with valid and invalid drafts.
9. Simulate interrupted work and restore a Recovery Draft.
10. Attempt to open a bad `.ggb` and confirm the current workspace is unchanged.
11. Load corrupt and newer metadata and confirm normal construction use without overwrite.

## Out of Scope

- Commercial use or obtaining a commercial GeoGebra agreement.
- User accounts, backend storage, cloud sync, sharing, collaboration, or GeoGebra sign-in.
- Mobile/touch-first authoring.
- Offline operation or self-hosting the GeoGebra bundle.
- Native desktop packaging.
- A complete LaTeX distribution or completion for unsupported TeX packages.
- Arbitrary GeoGebra commands, scripting/action commands, assignments, and multi-output commands.
- Raw GeoGebra-definition editing.
- Lossless or best-effort reverse parsing of arbitrary pre-existing dynamic text.
- Automatic recovery when an external rename match is ambiguous.
- Inline or segment-level opt-out from Sign Simplification.
- Protecting `\text{...}` from GeoGebra's `Simplify(Text)`.
- Live rendered preview before Apply.
- Silent synchronization or merging between browser tabs.
- Persisting invalid drafts as Applied Source inside `.ggb`.
- Reusing the old AWK program's complete-document `\[...\]` scanning or generated TeX-document workflow.
- Claiming accessibility behavior inside the embedded applet beyond what GeoGebra provides.
- Claiming support for a branded browser that has not passed the manual release checklist.

## Further Notes

### Empirical GeoGebra findings

These facts were probed against GeoGebra Classic HTML5 `5.4.920.0` and must remain covered by tests because some are undocumented or differ from the current reference:

- A custom unknown file added through `setFileJSON` is dropped by the next `getFileJSON`/`getBase64` export. This is why metadata uses a supported auxiliary text object.
- A base64url metadata text object survived export into a genuinely fresh applet with exact quotes, LaTeX backslashes, newlines, and Unicode. Invisible, auxiliary, fixed, and selection-disabled XML properties survived.
- Labeled text redefinition behaved in place and preserved the common presentation fields tested; position changed only when the new command explicitly supplied a different position.
- Dedicated rename listeners returned exact old/new labels. Generic client events arrived as arrays despite object-shaped documentation.
- Programmatic undo/redo reverted target and metadata together after one undo point but emitted generic undo/redo events rather than object update callbacks.
- Undo/redo was ineffective with `showToolBar:false` even when undo was enabled.
- Direct action commands could mutate the construction while `evalCommand` returned `false`; the boolean is not a transaction result.
- The final nested `FormulaText((expression))` form did not execute the tested `Delete`, `SetValue`, or `Execute` commands, but formatted them symbolically. They remain rejected for clarity and version resilience.
- Nested multi-output `Intersect` contributed only its first result and created no extra labels. Multi-output commands remain rejected.
- GeoGebra's parser does not treat `\"` as an escaped quote in a text literal. Literal quotes require segmented `UnicodeToLetter(34)`.
- Backslashes pass through GeoGebra text strings literally; doubling a LaTeX backslash changes the LaTeX payload rather than escaping it.
- `Simplify(Text)` performs global string rewrites, including inside `\text{...}`. The destructive behavior is an accepted default with explicit per-object opt-out.
- `FormulaText` may appear as `LaTeX` in `getCommandString`; source recovery must not depend on the spelling authored before evaluation.

### Assumptions fixed for implementation

- Crash recovery stores a local construction snapshot as well as drafts because drafts alone cannot restore a new, unsaved construction.
- The initial command catalog is intentionally small. Expanding it is compatible work only when the new command's overloads, result cardinality, reference scoping, completion, and browser behavior are tested.
- The auxiliary-object minimum capacity is an acceptance target, not a known GeoGebra guarantee. Failure to meet it requires an ADR revision before implementation continues.
- Actual branded-browser smoke tests unavailable to the implementation environment are human release steps. The automated suite produces the reproducible checklist and evidence needed for them.
- This repository has no implementation or prior test conventions. The stack, module interfaces, and tests in this specification establish the v0.1.0 conventions.
